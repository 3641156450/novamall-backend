## 一、项目经历（简历正文，两种写法选一个）

### 写法 A：按技术点分条（推荐，技术关键词密度高）

```
NovaMall 分布式电商后端                          2025.09 - 2026.01
个人项目 | GitHub: github.com/你的用户名/novamall-backend
技术栈：Spring Boot 3 / Spring Cloud Alibaba / Nacos / Gateway / OpenFeign /
        MySQL / Redis / RabbitMQ / MyBatis-Plus / Python(FastAPI) / Go / Docker

项目描述：从零设计并实现的分布式电商后端，包含网关、认证、商品、订单、秒杀、
任务调度 6 个微服务，覆盖注册登录、商品浏览、下单支付、秒杀抢购完整链路。

主要工作：
· 设计并实现商品三级缓存体系（Caffeine 本地缓存 + Redis + MySQL），
  使用布隆过滤器和空值缓存防缓存穿透、分布式锁双重检查防缓存击穿、
  随机 TTL 防缓存雪崩，热点商品查询 RT 从 45ms 降至 3ms
· 基于「本地消息表 + RabbitMQ」实现下单的分布式事务最终一致性：
  订单与消息在同一本地事务落库，事务提交后投递 MQ，
  失败消息由定时任务按指数退避重投，保证库存扣减不丢失
· 设计秒杀方案：使用 Redis Lua 脚本将「库存判断 + 重复购买校验 + 扣减」
  合并为原子操作，抢购成功后通过 MQ 异步落库削峰，压测 500 并发下无超卖、无重复下单
· 抽象公共模块实现注解式分布式锁、接口幂等（Token + Lua 原子消费）、
  令牌桶限流（Redis Lua），业务代码通过一行注解接入
· 实现 JWT 无状态登录（BCrypt 加密 + 退出黑名单）、
  网关统一鉴权、基于注解的 RBAC 权限控制
· 使用 Python FastAPI + Pandas 开发数据分析服务，
  提供热销榜、销售趋势、GMV 移动平均预测接口
· 使用 Go 编写零依赖 HTTP 压测工具（goroutine + channel），
  输出 QPS / P50 / P95 / P99 指标
· 编写单元测试（JUnit 5）、Docker Compose 一键部署脚本、
  GitHub Actions CI 流水线
```

## 四、简历里**不要**写的东西

| ❌ 不要写 | 原因 |
|---|---|
| "精通 Java / 精通 Redis / 精通微服务" | 应届生写"精通"会被重点追问，而且大概率翻车 |
| "熟悉高并发、高可用架构设计" | 没有真实线上经验，说了就是给自己挖坑 |
| "带领团队完成…" | 个人项目就写个人项目，被戳穿很尴尬 |
| "支持百万级并发" | 你没压测过 |
| "熟练使用 Spring Cloud 全家桶" | 只用了其中三四个组件就写清楚是哪几个 |
| 一堆没听过的框架名词 | 面试官会挑一个你不会的问 |
| "热爱编程、吃苦耐劳、团结同学" | 空话，占地方 |
